# 建築高度系統

[English / 建置指令與欄位規格](BUILDING-HEIGHTS.md)

建議的「全球建築底層 → 國家／洲級補強 → 缺值估算 → 按視野載入」方向可行。新版把原始資料與渲染高度拆開：原始高度、樓層和來源保持可追溯，再以匹配品質、量測年代及高度定義選擇候選值。

目前提供可執行的區域預處理工具、PLATEAU／EUBUCCO 自動範圍接入、其他向量／柵格的本機匯入，以及前端圖磚讀取。**專案尚未內建或代管整合後的全球資料集。** 未設定新的圖磚來源時仍使用 OpenFreeMap；原有圖磚的 5 公尺標記為來源不明的上游渲染值，不能反推成原始實測或缺值。

## 資料如何採用

- 以固定版本 Overture 作為底層，讀取完整 nullable 高度、樓層與逐欄位來源。Overture 已整合 OSM，避免再疊一份 OSM 建築。也可用保留原始標籤的 OSM 區域檔作為底層。
- 日本依範圍查詢 PLATEAU 建物 CityGML；歐洲依 EUBUCCO 的實際行政邊界及儲存分片查詢。新增國家是新增來源登錄與轉換器，沒有展示城市名稱的分支。
- 在等面積座標進行輪廓交集匹配；交並比至少 0.65，模糊鄰棟、一對多及整棟對部件的高度傳遞會被拒絕。庭院孔洞參與匹配。
- 量測／圖上標記高度優先，其次是樓層換算，再來是模型／細緻柵格估算與區域估算。每一類內考慮年代、匹配及高度定義；資料發布年、建成年不會充當量測年。
- 最後缺值使用同用途、相近面積、附近至少五筆非估算高度的中位數；樣本不足才使用保守的用途／面積預設。全部標明估算性質，原始缺值仍保留。

已選值、原始值及所有替代／拒絕候選分開儲存；高度衝突有旗標。完整紀錄存於 `audit.jsonl.gz`，瀏覽器只拿輪廓與精簡來源欄位。3DBAG 以屋頂高程扣地面高程，EUBUCCO 的 `height_source=estimated` 不會當成實測，粗解析度衛星資料也不會偽裝為逐棟精度。

## 執行與目前界線

依[英文操作文件](BUILDING-HEIGHTS.md#build-a-partition)建立獨立 Python 環境，以經緯度矩形建置分區。輸出 zoom 14 GeoJSON 圖磚、manifest、稽核檔及統計報告；圖磚保留完整輪廓，以固定 ID 跨圖磚去重。多個不重疊分區可以合成同一份 manifest。

建置時設定 `VITE_LUMEN_BUILDING_MANIFEST_URL` 即可接入。前端沿用桌機／手機 4／2 個下載併發與共用 24／8 MiB 快取；國家資料匹配留在離線階段。底圖、道路、植被及車流維持原來管線，已審核地標保持自己的模型與高度。完成建置的範圍使用新建築，其餘範圍保留既有資料。兩種輪廓來源交界仍須檢查小幅錯位或重複，正式資料應覆蓋目標視野以外的緩衝區。

新來源出現在雙語介面，也會附於使用新資料的 PNG／GIF／影片。原有 3D 場景檔仍依賴部署端的線上圖源版本；舊版唯讀播放器不變。GeoJSON 適合第一版檢查與靜態託管，請啟用 HTTP 壓縮。正式全球規模仍需資料儲存、流量估算、排程、分區整併，以及可能的 MVT／PMTiles 編碼；本次工具不代表全球已全部完成建置。

## 參考資料的取捨

完整來源清單與官方連結見[資料評估表](BUILDING-HEIGHTS.md#data-review-and-licensing)。主要修正如下：

- GBA 官方資料授權為非商業用途，適合研究比較，不能當成通用開源發行的預設資料。
- EUBUCCO v0.2 混合既有來源與預測值，而且 Prague／Abruzzo 有授權例外；預設管線排除涉及這些來源的資料。
- Google Open Buildings 2.5D 有特定區域覆蓋，不能當作日本、台灣或全世界的保證補值來源。
- WSF 3D、TEMPO 及其他較粗網格應作區域背景估算。Microsoft 建築辨識信心不等於高度信心。
- 台灣國土測繪中心有公開圖臺與服務，但大量下載、衍生資料再散布需要確認適用條件，因此尚未啟用自動批次接入。
- Re:Earth Buildings 可參考圖磚服務設計；VoxCity 可參考地理範圍自動選源。此實作延續既有 Three.js 建築幾何，不引入另一套體素或 3D Tiles 渲染器。

所有資料授權獨立於應用程式的 AGPL。新增來源前要確認來源的高度定義、年代、缺值碼、座標系統與再散布條件，保留署名及稽核紀錄。
