# Lumen Streets 3D

[English](3D-ARCHITECTURE.md)

3D 版本是與原版並存的開發預覽，將航拍金夜帶入可持續移動、轉動鏡頭並有真正深度的地圖。目前尚未取代原版發行版。

## 執行與操作

使用 Node.js 24，執行 `npm ci`、`npm run dev:3d`，開啟 `http://127.0.0.1:5183/three.html`。原版保留於 `/index.html`。正式建置使用 `npm run build`、`npm start`，在 5180 連接埠開啟 `/three.html`。

拖曳移動、右鍵拖曳旋轉與傾斜、滾輪縮放。水平旋轉固定為每像素 0.25 度，畫面上下方的同向拖曳方向一致。手機可用雙指縮放和旋轉。「探索城市」選擇預設街區或搜尋；「光影與車流」調整燈光、車流、俯瞰角度、環繞及解析度。隱藏控制後可專心欣賞夜景。

## 已完成

- 全球向量圖磚隨鏡頭載入與卸載，不再受固定街區邊界限制。
- 桌機預設縮放 13.65、手機 13.35，最近限制為 16.5，最大傾斜 55 度。相較前版 14.5 上限可再按兩次「＋」，預設俯瞰距離不變。建築到縮放 12.3 仍保持完整高度，12.3 至 11.8 之間逐漸轉回地圖；12.8 起顯示車流。
- 收斂的香檳色道路光邊包圍暗色路面，搭配分散的路燈亮點與克制的光暈。低飽和藍灰屋頂襯托成組的象牙白、冷色窗光；公園使用深暗的不規則樹冠，水面加入隨鏡頭轉動的岸燈倒影。硬體深度測試負責建築、地標與動態燈光遮擋。
- 八個原版快照保留 OSM 高度、樓層、建築組合、庭院孔洞及六個已校對地標。曲面與開口轉為真實三角形；矩形雙坡屋頂有對應生成器，未支援形狀暫用平頂。
- 延用原版種子車流、道路需求、單行道、號誌、跟車與轉彎；快照保留模擬列車。同一快照重建時，保留仍存在路段上的車流。
- 支援 PNG、GIF、短影片、視角連結、嵌入模式與本機 GLB 匯入；介面提供英文及繁中。

## 技術選擇

### 美術基準

夜景應由亮窗與個別路燈構成，燈光之間保留暗部。道路連接構圖，但不應變成整條發亮的光帶；bloom 集中於最亮的燈點。降低道路亮度時，不能只把整個場景一起壓暗。亮度控制與地圖風格共用道路預設值，回到 100% 就恢復這組基準。

屋頂色彩低調，立面分格、窗戶比例及房間亮暗依建築穩定變化；這是美術材質，不代表實地調查的立面。遠景整合窗光能量，避免細小立面變成全黑。植被比建築安靜，水域中央保持深暗，稀疏暖色倒影對應可見的推估岸燈。來源建築高度與河道輪廓維持不變。

車燈依鏡頭方向區分車頭與車尾，沿目前道路取樣短光跡，最長八公尺、每車最多兩個點；停車時保持清楚光點。這個顯示效果不保留歷史畫格，不改動車速、需求、路線或匯出保存的模擬狀態。鏡頭範圍與預設俯瞰距離維持不變。

### 繪圖後端

MapLibre GL JS 6.9.1 和 Three.js 0.186.0 共用 **WebGL 2** context 與深度緩衝。MapLibre 負責全球地圖、鏡頭、來源 Worker 及圖磚快取；Three.js 負責合併的立面網格、路燈、車輛與匯入地標。尚未實作 WebGPU。

[Streets GL](https://github.com/StrandedKitty/streets-gl) 使用向量圖磚生成 OSM 幾何，搭配自製 WebGL 2 與完整後製；其文件建議使用獨立顯卡，不能直接當作本專案的手機效能基準。[MapLibre 官方範例](https://maplibre.org/maplibre-gl-js/docs/examples/add-a-3d-model-using-threejs/) 說明與 Three.js 共用鏡頭及 context；[OpenFreeMap](https://openfreemap.org/quick_start/) 提供初期全球資料來源。參考的是架構分工，沒有複製參考作品的美術。

Bloom 複製一次完成的共用畫面，在寬高各四分之一的緩衝區擷取、模糊亮部，再合成回原圖。使用無深度的 RGBA8 貼圖，城市幾何只繪製一次。這仍增加顯示頻寬成本，但不需要浮點目標、陰影貼圖或大量實體光源。後續若導入 WebGPU，應先以實測確認收益。

## 資料界線

建置時可設定 `VITE_LUMEN_TILEJSON_URL` 指向相容 OpenMapTiles 的 TileJSON，預設為 `https://tiles.openfreemap.org/planet`。需要 building、transportation、water、landuse、landcover、park 等圖層。公開服務並無可用性保證，正式部署可自架相容圖磚。連續移動不呼叫公開 Overpass；搜尋沿用原本受限制的伺服器閘道。

預設街區附近使用原版 OSM 快照建立較完整建築與路網，周圍由全球圖磚延伸。其他地點使用圖磚高度及保守推估，依量化座標推導交叉口。全球圖磚未保留完整標籤與原始 OSM 節點身份，因此屋頂、建築關聯、車道及立體交叉口仍不完整；快照邊界兩側也尚未形成完全持久、統一的交通網路。全球列車尚未實作。

即使選擇預設街區，目前仍需要全球圖磚網路。連線問題會顯示重試提示；完整離線底圖留待後續。預設街區保留原版地景，新的地景材質疊於其上。水面、公園、林地、草地與橋面從既有的層級 14 建築圖磚一起解析，不增加地景網路請求；多邊形孔洞保留島嶼與空地。樹冠是程序表面明暗，不是逐棵樹木網格。倒影使用有上限的道路燈光與推估岸燈場，朝鏡頭延伸並限制於實際水域；屬於風格化效果，並非螢幕空間反射或真實路燈調查。河道不會為配合美術參考而加寬。地景幾何達上限時仍保留底圖。

上限不包含瀏覽器額外成本及地圖引擎的可見圖磚緩衝。Bloom 保留一張全尺寸 RGBA8 貼圖與兩張寬高各四分之一的目標：1664 × 936 約 6.7 MiB，3840 × 2160 匯出約 35.6 MiB；匯出結束後恢復顯示尺寸。可手動降低解析度；自動模式在計時器節奏變慢時降低像素倍率。這是保守啟發式控制，並非 GPU 效能測量或幀率保證。

建模同時最多一項執行、另一項合併等待；鏡頭移動時取消過時工作並檢查版本。建築載入與底圖縮放分開，因為較遠的底圖本身省略了個別建築，單改顯示門檻無法解決。Worker 以固定來源層級 14、從中央優先分批下載，每次只解析及建模一個圖磚，快取只保留壓縮資料。緩衝區重複片段依外框中心歸屬圖磚，跨邊界裁切片段分別保留。只保留一份已解析快照，使用局部公尺座標維持精度。

精細立面有固定頂點預算，超出後改用符合建築方向與來源高度的實例量體，不再直接消失。遠景實例超過目標時，相鄰小型低樓合併為有人造量體占據的格網；高樓與大型建築分開保留，因此目標不是硬性上限。簡化量體不保留精確輪廓和庭院；建築統計代表來源片段涵蓋量，不是唯一 OSM ID 或 GPU 實例數。外圍圖磚另外設有上限，達到時會明確提示；極寬或高傾斜視野仍可能有外圍載入不完整的情況。

場景替換會釋放舊模型、地景燈光影像／貼圖與路燈 GPU 緩衝，過時 Worker 回覆的影像也會關閉；同一預設街區重用原版地面貼圖。轉回地圖時另釋放 bloom 目標、地景與車流，並清除 Worker 建築快取。離開頁面會結束 Worker 並釋放渲染器。背景頁面停止車流繪製；暫停後僅因互動更新。建築 GPU 幾何數字不含地景資源、地面影像／貼圖、Worker 解析資料、底圖緩衝與瀏覽器成本，不代表總記憶體。

## 匯出與分享

PNG 保留目前長寬比，最長邊可選 1920、2560、3840 像素；直式視窗得到直式圖片。GIF 為 6 秒、10 fps、最長邊最多 720 像素，使用固定色盤、一次只傳一幀。影片以 Mediabunny 接 WebCodecs，使用固定 30 fps 時間戳，可選 6、15、30 秒；優先 MP4／AVC，不支援時改用 WebM／VP9，尺寸取偶數。逐幀渲染並等待編碼器接收，因此編碼較慢不會縮短片長。沿用原版暫存檔串流輸出，大於 1920 px 的工作需要瀏覽器暫存檔支援，輸出上限 128 MiB。長時間桌布及無縫循環仍留待後續。

匯出暫停操作並保存車流、時間、播放及解析度，使用相同渲染器取景；成功、失敗或取消都恢復編輯狀態。這能避免再配置一整份地圖，但期間會占用編輯器。所有作品附上地圖來源。

分享連結保存鏡頭、燈光、車流密度、預設城市及語言，嵌入模式隱藏編輯控制。開啟時重新取得圖磚並重啟車流，不是完整可重現的場景檔；不包含本機匯入的 GLB。詳見 [模型指南](3D-LANDMARKS.zh-TW.md)。

## 驗證與程式分工

介面在 `src/three/main.js`、`style.css`、`locales.js`；地圖風格在 `style.js`；`stream.js` 和 `city.worker.js` 負責有預算的載入與建模。`geometry.js`／`geo.js` 處理實體網格與座標，`materials.js`／`layer.js` 負責 GPU 繪圖、車流和釋放，`export.js`／`gif.worker.js` 負責匯出恢復，`model-import.js` 驗證 GLB。

執行 `npm test`、`npm run check:presets`、`npm run check:docs`、`npm run build`。啟動開發伺服器後，`npm run check:3d:browser` 使用已安裝的 Edge 測試真正匯出、旋轉、跨城移動、遠景釋放和手機尺寸。證據輸出至不追蹤的 `artifacts/3d/`。手機尺寸模擬不代表已驗證 Android／iPhone 實機效能。

`node scripts/check-3d-aerial.mjs` 另外驗證畫面上、中、下方的真實右鍵拖曳、最近縮放限制、上海全城遠景、札幌全球載入、地圖模式釋放與直式構圖，輸出至 `artifacts/3d-revision/`。`view.js` 統一鏡頭門檻，`tiles.js` 處理建築圖磚，`surface.js` 與 `volumes.js` 處理地景貼圖及遠景量體。

`bloom.js`、`environment.js`、`environment-layer.js` 負責畫面光暈、地景遮罩、植被及反射燈光。`node scripts/check-3d-art.mjs` 在開發伺服器上擷取固定札幌視角，驗證多出的兩級「＋」、3840／1920／3840 PNG 匯出與狀態恢復、倒影旋轉、重複切換地圖後的資源釋放及手機尺寸，輸出至 `artifacts/3d-art/`。截圖仍需實際目視審查，不能只以斷言通過當作美術驗收。

`node scripts/check-3d-facades.mjs` 以六個種子、三個透視角度，檢查精細網格與實例量體的實際 GPU 隨機值傳遞。建築種子使用 flat 插值保持固定，避免微小插值誤差讓相鄰像素切換窗戶亮暗或立面樣式。測試包含修正路徑與 smooth 插值對照組，並把札幌近景、旋轉截圖存於 `artifacts/3d-facades/`。
